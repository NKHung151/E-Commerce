# Product Service

## Overview
Owns the product catalogue: products, their category-specific details (book, electronics, ...),
stock and ratings. Reads are public; writes are for staff and admin. It also takes part in the
order saga (reserving and restoring stock) and reports product views to the AI service.

## Port
- **8002** (internal service port)
- Accessed via the Nginx gateway at `http://localhost:8080/api/v1/`

## Database
- **PostgreSQL**, database `product_db`
- Migration `0002_seed_products` loads the 300-product demo catalogue (`product_app/seed/products.json`,
  generated by `infrastructure/seed/generate_seed_data.py` to match the AI behaviour log)

## Models
- **Product**: name, sku, description, price (Decimal 12,2), discount (%), stock, image_url, rating
  (0-5, read-only: average of the reviews, set by comment-rate-service), is_available, views,
  category (id in catalog-service)
- One detail model per category, linked one-to-one to Product:
  Book (author, publisher, isbn), Electronics (brand, warranty months), Fashion (size, color),
  HomeLiving (material, dimensions), SportsOutdoors (sport_type, weight), BeautyHealth (ingredient,
  volume), ToysGames (age_range, players), Automotive (vehicle_type, compatibility),
  FoodGrocery (expiry_days, weight), OfficeSupplies (pack_size, material)
- **StockReservation**: stock taken for an order, so the saga can restore it

## API Endpoints

### Storefront and services — `/api/v1/products/`
- `GET /products/` - Paginated list (`page`, `page_size` ≤ 100). Filters: `search` (name, description),
  `category_id`, `min_price`, `max_price`. `personalized=1` orders the list with the AI service's
  recommendations for the user in the JWT.
- `GET /products/{id}/` - Product with `category_name` and `details`. `increment_view=true` counts a view
  and, for a logged-in user, reports it to the AI service.
- `POST /products/{id}/update_rating/`, `reduce_stock/`, `rollback_stock/` - internal
  (`X-Internal-Token`) or staff/admin

### Back office — `/api/v1/staff/`
- `GET|POST /staff/products/`, `GET|PUT|PATCH /staff/products/{id}/` - staff or admin. A PATCH may carry
  `details: {...}` to edit the category-specific fields (validated, 400 on bad values).
- `DELETE /staff/products/{id}/` - admin only
- `POST /staff/{books|electronics|fashion|home-living|sports-outdoors|beauty-health|toys-games|automotive|food-grocery|office-supplies}/`
  - create a product and its details in one request (also list / retrieve / update / delete)

Every create / update / delete through the API asks the AI service to rebuild its search index
(after commit, in the background). Stock changes made by the saga do not.

## Integrations
| With | How | Purpose |
|---|---|---|
| catalog-service | HTTP, cached 5 min | `category_name` of a product |
| ai-service | HTTP + `X-Internal-Token` | personalised ordering, index rebuild after catalogue changes |
| ai-service | RabbitMQ `user-behavior-queue` (HTTP fallback) | `view` events; one background publisher thread with a persistent connection |
| RabbitMQ `saga-events` | consumes `saga-payment-success/pending`, `saga-payment-refunded`, `saga-order-cancelled`; publishes `saga-stock-reduced/failed` | reserve stock atomically (row locks, idempotent per order) and restore it on compensation |

## Setup & Running

### Local Development
```bash
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py runserver 0.0.0.0:8002
```

### Docker
```bash
cd infrastructure
docker compose up -d --build product-service
```

## Example Requests

```bash
# List / filter
curl "http://localhost:8080/api/v1/products/?search=laptop&max_price=25000000&page_size=5"

# Create an electronics product (staff)
curl -X POST http://localhost:8080/api/v1/staff/electronics/ \
  -H "Content-Type: application/json" -H "Authorization: Bearer <access_token>" \
  -d '{"product": {"name": "New Laptop", "price": "19990000", "stock": 20, "category": 2},
       "brand": "TechBrand", "warranty": 24}'
```
